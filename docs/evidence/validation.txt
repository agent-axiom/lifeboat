- Contract acceptance was required before running the workflow.
- Issue 3 changed from Closed to Open, retained bug, added priority, and
  advanced from revision 1 to revision 2.

- A reload preserved the modified issue and accepted contract.

  original Closed/bug snapshot and the current Open/bug/priority state.

  conclusively exercised through the automation interface.

BLOCKER: FRESH BROWSER-DOWNLOADED PLAYER

After stopping the test Studio, the generated Player exited with code 137
before starting its server. The downloaded executable had the macOS
quarantine attribute. Its on-disk code signature verified, but Gatekeeper
assessment rejected it. The executable SHA-256 was identical across the
new ZIP, the bundled Studio Player, and the previously tested Astra Player:
89c88f3539724a6a5dd4fe91981126cd6211678388ba73a9a2ef77f36454eb84

This rules out a binary-content mismatch in that check; it does not make
the fresh-download experience successful. Developer ID distribution signing
and notarization remain unresolved. System protection was not disabled and
quarantine was not removed. A fresh independent Player run was NOT passed.
